# Code of Conduct

## Why this document exists

This project deals with death, incapacitation, inheritance, and the people left behind to sort through what a stranger's protocol did with someone's assets. Contributors will, at various points, be discussing scenarios involving grief, family conflict, and financial loss — sometimes drawn from their own experience, since that is often what motivates someone to file a spec critique in the first place. The bar for how this community treats each other is set accordingly higher than it would be for a project with lower stakes.

This is not a boilerplate community-health file included because platforms expect one. It is a working document, and it is enforced.

## Expected behavior

- **Engage with the argument, not the person.** A critique of `spec/SPEC.md` section 7 is welcome, however sharply worded the underlying disagreement. A critique of the person who wrote it is not, regardless of how it is phrased.
- **Assume good faith on first contact, and adjust based on evidence.** Most people filing an issue about a scenario the protocol handles badly are describing something real. Treat it that way until shown otherwise.
- **Disclose relevant conflicts of interest.** If you maintain or are compensated by a platform proposing to become, or already competing with, a `DLPAdapter` implementation, say so when it is relevant to a discussion — this keeps design debates about the merits rather than about undisclosed incentives.
- **Respect the non-engineering contributions this project explicitly asks for.** Spec critique from people who are not developers is, per [CONTRIBUTING.md](CONTRIBUTING.md), some of the most valuable input this project receives. Treat it with the same seriousness given to a pull request.
- **Report security issues the way [SECURITY.md](SECURITY.md) describes**, not in a public issue — this protects everyone currently relying on the reference implementation, not just the maintainers.

## Unacceptable behavior

- Harassment, intimidation, or personal attacks directed at any contributor, in this repository or elsewhere in connection with participation here.
- Discriminatory language or conduct related to a person's identity, background, or circumstances — including, given the project's subject matter, conduct that trivializes or mocks a contributor's disclosed experience with death, grief, or family estate disputes.
- Publishing a working exploit against the cryptography or the quorum state machine without following the private disclosure process in [SECURITY.md](SECURITY.md).
- Deliberately misrepresenting the protocol's current maturity — for instance, describing an untested or unimplemented capability as production-ready, in a way likely to lead someone toward relying on it with something real.
- Sustained bad-faith argument: repeating a claim after it has been directly and substantively addressed, without engaging the response.

## Scope

This code of conduct applies within all project spaces — the repository itself (issues, pull requests, discussions, security advisories) — and in any other setting where someone is acting as a representative of this project, such as presenting the protocol at a conference or discussing it in an official capacity elsewhere.

## Enforcement

Reports of unacceptable behavior can be raised through the same private channel described in [SECURITY.md](SECURITY.md) for security issues, since this project does not yet have a separate conduct-reporting address. Reports will be handled discreetly, with the identity of the reporting party disclosed only as strictly necessary to investigate.

Given this is an early-stage project with a single primary maintainer (see [GOVERNANCE.md](GOVERNANCE.md)), enforcement decisions currently rest with that maintainer. As the project's contributor base grows, enforcement authority is expected to move toward a small conduct committee separate from the technical maintainers, consistent with the general shift toward structured governance described in [GOVERNANCE.md](GOVERNANCE.md).

Possible responses to a substantiated report include a private warning, a request for public correction or apology, temporary suspension from project spaces, or a permanent ban — chosen in proportion to the severity and pattern of the behavior, not applied as a fixed schedule.

## Attribution

This document was written specifically for this project rather than adapted wholesale from a generic template, in keeping with the project's general preference — stated throughout [CONTRIBUTING.md](CONTRIBUTING.md) and the [WHITEPAPER.md](WHITEPAPER.md) limitations section — for saying precisely what applies here rather than what applies to open-source projects in general.
